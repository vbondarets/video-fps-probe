# Browser benchmark

Generated by `npm run bench` (`scripts/bench/run-bench.mjs`). The built app in `dist/` is served by a local `node:http` server (127.0.0.1, `Cache-Control: no-store`, no compression) and driven over the Chrome DevTools Protocol in headless Chrome with a throwaway profile. Files go through the real file input (`DOM.setFileInputFiles` with absolute paths), so every `File` is disk-backed, as when a user picks files. Times are wall-clock milliseconds on the machine below; `ms` is the analysis inside the worker (`FileResult.io.ms`, from the start of `analyze()` to the result, including any lazy parser chunk load), `UI ms` is measured in the page from the input's `change` event to the DOM update that shows the last result. Every number comes from one run of the bench on one desktop; with a 0.1 ms clock and other processes on the machine, differences of a few tenths of a millisecond between engines or browsers are noise.

## Key numbers

- Own engine, warm, Chrome: per-fixture median **1.60 ms** (p90 2.00 ms, slowest 2.80 ms for `h264_vfr_remux.mkv`); UI time from file pick to rendered result median 2.50 ms.
- I/O: median 2 reads per file (max 2); 6.98 MiB read of 9.23 MiB in total (75.6%), median 98.7% of a file.
- Cold batch: 100 files picked at once on a fresh profile: all results rendered after **268 ms** (worker time summed over files 217 ms, two workers); the same batch on a reloaded page took 265 ms (median of 5, range 259-282 ms).
- Cold first ISO BMFF file (`cfr_h264_30.mp4`): **14.4 ms** from pick to rendered result on a freshly loaded page, against 2.80 ms once warm, so the first file of that container costs about 11.6 ms extra (worker start, worker entry and parser chunk fetch and compile, first unoptimised run).
- Cold first Matroska file (`h264.mkv`): **15.2 ms** from pick to rendered result on a freshly loaded page, against 2.70 ms once warm, so the first file of that container costs about 12.5 ms extra (worker start, worker entry and parser chunk fetch and compile, first unoptimised run).
- mp4box: 69 fixtures, median 1.90 ms per file (geometric mean 1.2x the own engine); same average and frame count as the own engine on 61 of 69.
- mediabunny: 96 fixtures, median 1.30 ms per file (geometric mean 0.9x the own engine); same average and frame count as the own engine on 61 of 96.
- rVFC: 11 of 13 files produced an estimate (9 equal to ffprobe's average); 1.94 s median, 4.85 s max per file.
- Chrome vs Node (same own engine): 102 of 102 results identical (all fields except timing).
- Edge, warm own engine: per-fixture median 1.60 ms; geometric mean 0.95x Chrome.
